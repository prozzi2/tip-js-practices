## 7. Задание 4 — план по дням

Проверки проведены тем же способом в Node.js. Цикл `while` распределяет оставшиеся задачи по дням. Выражение `Math.min(dailyLimit, remainingTasks)` ограничивает объём работы на последнем дне. Положительный целый лимит гарантирует уменьшение остатка и завершение цикла. Лимит проверяется даже при отсутствии оставшихся задач.

| Вход: totalTasks, completedTasks, dailyLimit | Ожидание | Фактический результат | Итог |
|---|---|---|---|
| `12, 5, 3` | 3 дня; задачи по дням: 3, 3, 1 | Осталось задач: 7 / День 1: выполнено 3, осталось 4 / День 2: выполнено 3, осталось 1 / День 3: выполнено 1, осталось 0 / Потребуется дней: 3 | Пройдено |
| `10, 4, 3` | 2 дня; по 3 задачи | Осталось задач: 6 / День 1: выполнено 3, осталось 3 / День 2: выполнено 3, осталось 0 / Потребуется дней: 2 | Пройдено |
| `5, 3, 10` | 1 день; 2 задачи | Осталось задач: 2 / День 1: выполнено 2, осталось 0 / Потребуется дней: 1 | Пройдено |
| `5, 5, 2` | Сообщение о завершении; Потребуется дней: 0 | Все задачи уже выполнены. / Потребуется дней: 0 | Пройдено |
| `0, 0, 2` | Сообщение о завершении; Потребуется дней: 0 | Все задачи уже выполнены. / Потребуется дней: 0 | Пройдено |
| `5, 2, 0` | Ошибка; цикл не запускается | Ошибка: количество задач не может быть отрицательным, а дневной лимит должен быть не меньше 1. | Пройдено |
| `5, 2, 1.5` | Ошибка; цикл не запускается | Ошибка: все значения должны быть целыми числами. | Пройдено |
| `5, 6, 2` | Ошибка; цикл не запускается | Ошибка: количество выполненных задач не может превышать общее количество задач. | Пройдено |

Дополнительно проверено: нулевой лимит и строковый лимит при отсутствии задач, а также Infinity вместо общего количества. Во всех трёх случаях выведена ошибка, цикл не запускался.

**Вариант 1:** проверка `12, 5, 3` приведена в первой строке таблицы. Потребуется 3 дня; по дням выполняются 3, 3 и 1 задача.

| Ошибка | Что наблюдалось при запуске | Причина | Исправление | Результат |
|---|---|---|---|---|
| Обработка количества задач | Выполнено 32, осталось −24 | Оператор + объединял строки «3» и «2»; вычитание затем преобразовывало «32» в число | Number() перед вычислениями | Выполнено 5, осталось 3 |
| Граница цикла | Контрольная сумма 6 | Условие taskNumber < 4 исключало число 4 | taskNumber <= 4 | Контрольная сумма 10 |

### Разбор границы цикла

Ниже приведена трассировка по коду исправленного цикла; это разбор алгоритма, а не протокол пошаговых действий в DevTools.

| `taskNumber` | Проверка `taskNumber <= 4` | `controlSum` до сложения | `controlSum` после сложения |
|---|---|---|---|
| 1 | `true` | 0 | 1 |
| 2 | `true` | 1 | 3 |
| 3 | `true` | 3 | 6 |
| 4 | `true` | 6 | 10 |
| 5 | `false` | 10 | Цикл завершён; сумма остаётся 10. |

При исходном условии `taskNumber < 4` выполнение прекращалось уже при значении 4, поэтому сумма составляла `1 + 2 + 3 = 6`. Условие `<= 4` включает последнюю итерацию: `1 + 2 + 3 + 4 = 10`. Итог 10 подтверждён запуском исправленного файла в Node.js.

Другая ошибка связана с исключением последнего значения диапазона условием < вместо <=.

Остановка в DevTools позволяет видеть промежуточное состояние: сумма уже равна 5, а остаток ещё не вычислен. Так можно проверить порядок выполнения и значения переменных до получения итогового вывода.
